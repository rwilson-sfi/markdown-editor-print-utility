### Objective

Investigate the user's report that sending a Markdown file to the Microsoft Print to PDF printer
"errors out or nothing at all happens," and fix the cause.

### Findings (evidence: Application event log, live process/pipe inspection)

- The failure is not in the print path. Every recorded MarkdownEditor error is one of two startup
  failure classes; no print-time errors exist in the log.
- Class 1 — single-instance hand-off crash (app defect): secondary launches on 2026-08-31 (10:48,
  11:22 ×2) and 2026-09-02 (09:34 ×3) died with an unhandled `UnauthorizedAccessException` from
  `NamedPipeClientStream` connect inside `SingleInstanceCoordinator.SendOpenFilesAsync`, called from
  `App.OnStartup`. The 10:48 event message — "Could not connect to the pipe because it was not owned
  by the current user" — shows the then-running primary was started in a different security context
  (consistent with an elevated launch). The catch filter in `App.OnStartup` covered only
  `IOException`/`TimeoutException`/`OperationCanceledException`, so `async void OnStartup` turned the
  exception into process death before the file ever opened.
- Class 2 — host application control (not an app defect): `FileLoadException: Access is denied`
  loading freshly built assemblies, recorded 2026-08-24 (20:24–20:29), 08-25, 08-29, 08-31
  (10:44–10:45), and reproduced tonight (21:07) with a fresh Debug build in `C:\SFM\Dev`. Fresh
  unsigned binaries are denied on first execution in both `C:\AI-Workspace` and `C:\SFM\Dev`;
  previously executed binaries keep running. This extends the 2026-08-24 lesson that treated
  `C:\SFM\Dev` as unaffected.

### Work performed

- Broadened the hand-off failure handling in `App.OnStartup` to catch every exception and show an
  actionable dialog (specific text for the different-permissions case and for timeouts) instead of
  crashing.
- Hardened `SingleInstanceCoordinator.ListenAsync` so a pipe name owned by another security context
  no longer kills the listener task; it retries every five seconds and recovers when that process
  exits.
- Committed as `28df687` on `host/sfi-p14-2255`.
